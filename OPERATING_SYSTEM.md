# OPERATING_SYSTEM.md

Purpose: minimal live operating model for proof-of-work execution.

## Core rule

A work cycle only counts if it ends in one of these:
- material artifact advanced
- worthwhile finding captured in the correct durable surface
- substantive user-facing update sent
- verified system/config change completed
- real blocker surfaced with exact next dependency

If none of those happened, the cycle did not produce forward motion.

## Active lane rule

A lane is active only if it has all four:
- clear objective
- current next proof
- bounded working surface
- default output path

If a lane lacks one of these, it is not active. It is background context.

## Lane status authority

`ACTIVE_WORK.md` is the authoritative live lane snapshot.
If this file and `ACTIVE_WORK.md` disagree, follow `ACTIVE_WORK.md`.

## Anti-fake-progress rule

These do not count as progress by themselves:
- checking
- reviewing
- rewriting prompts
- cleaning instructions
- creating a new control layer
- describing a lane better without changing an artifact or surfacing a blocker

## Blocker rule

Surface a blocker immediately when:
- the next meaningful action cannot be taken
- required access or a dependency is unavailable
- a mechanism is not changing behavior after repeated cycles
- continued autonomous action would likely create waste or drift

A blocker update must include:
- what is blocked
- why
- exact next dependency

## System change rule

Only make autonomous system changes that are:
- small
- reversible
- clearly simplifying or unblocking
- likely to produce fast visible usefulness

Do not add a new supervisory or governance layer unless failure analysis proves it is necessary.

## Learning rule

Capture lessons only when they change future behavior.
Use small durable notes, not sprawling meta-systems.
